## 1. 方針

**「測る道具を先に作る」順にする。** M0（続けるかの判断）は次の3つの数字で決まる。

| # | 指標 | 判定の目安（計画書 7章） |
|---|---|---|
| M0-1 | キック・スネア・ハイハットの採譜の F 値 | 0.85 以上 |
| M0-2 | 切り出した音で組んだキットの聞き比べ | 半数以上の曲で「同じキットに聞こえる」 |
| M0-3 | エフェクトの当てはめ前後の多重解像度 STFT 距離 | 当てはめ前より明確に下がる |

モデルを触る前に評価用ステムと採点スクリプトを用意し、以後は毎週同じ物差しで測る。

計画書 9章の4項目はそのまま使い、順番と中身を次の3点だけ変える。

1. **採譜の F 値には「打点ごとの正解」が要る。** 9章の1は区間（Intro／Verse／Chorus）のラベルだけだが、F 値は打点の時刻と種類の正解が無いと出せない。20本を手で打点ラベルするのは重いので、半分は「自分の曲の MIDI から書き出した音を、Demucs などで分離し直したもの」にして正解 MIDI を無料で手に入れる。残りは他人の権利の明確な素材で、手ラベルは短い区間（例: 30秒）だけに限る。
2. **エフェクトの当てはめは、乾いた音の基準が Phase 0 には無い。** 計画書 3.5 は (b) 内蔵ライブラリか (c) モーダル音を「エフェクト前」とみなすが、どちらも Phase 0 には無い。代わりに手持ちのワンショット数個に既知の EQ・コンプ・リバーブを掛けた**合成テスト**を作り、正解のパラメータとの差と STFT 距離の下がり方で評価する。実ステムでの試行はその後に回す。
3. **JUCE の空のプラグインは最初の1〜2週で片付ける。** 解析とは独立で、Windows のビルド環境・pluginval・GitHub Actions のつまずきは早く知るほど安い。

## 4. 採点の決めごと（先に固定する）

- **採譜の F 値**: 打点の時刻の許容誤差は ±50 ms（ADT の研究で標準的な値。`mir_eval.onset` の既定値と同じ）。種類ごとに P・R・F を出し、M0-1 はキック・スネア・ハイハット（閉・開を区別しない）の3種の F 値の平均で判定する。強さ（ベロシティ）は Phase 0 の判定に入れない。
- **STFT 距離**: 窓長 2048・1024・512・256・128（ホップは窓長の 1/4）の STFT について、振幅スペクトルの対数の L1 距離とスペクトル収束（spectral convergence）の和を平均する（Yamamoto ら 2020 の Parallel WaveGAN、Steinmetz らの auraloss と同じ形）。
- **聞き比べ**: 曲ごとに「元のステム」と「切り出した音で組んだキット＋採譜 MIDI の再生」を A/B で聞き、「同じキットに聞こえる／違う」の2択で記録する。本人1人の判定でよいが、曲の順番を無作為にして日を分けて2回やる。
