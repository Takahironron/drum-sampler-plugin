# Phase 1（MVP「ステム → 鳴るキット」）の作業順

- 作成日: 2026-11-03
- 前提: M0 判定（`docs/phase0/M0判定.md`）は「続ける」で確定。M0-2・M0-3 は合格、M0-1 は 0.77（目安 0.85）で未達。
- Phase 1 の目標（計画書 7 章）: **M1（内部アルファ）= ステムを落として 1 分以内（3 分の曲）にキットが鳴り、MIDI で DAW に渡せる。** 期間の目安 3〜4 か月（根拠のある数字ではない）。
- 内容（計画書）: 解析 ①〜④（5 種の採譜、切り出し、自動の割り当て）、サンプルのエンジン、チョーク、パートごとの簡単な EQ・コンプ、A/B 比較、採譜の修正、MIDI の書き出し、個別出力。

## 1. 方針

1. **製品の経路を先に通す。** Phase 0 の M0-2 は SpectraLayers のパート別ステムと、その打点検出に依存していた。製品では「採譜 → パート分け → 切り出し」を自前で行う必要があるので、最初の 2 週間でこの経路を Python で通し、SpectraLayers のパート別ステムを**正解の代わり**にして測る（分離の質の物差しが手元にある）。
2. **Python で出た `kit.json` を JUCE で鳴らす形から始める。** 解析を C++ に移す前に、Python の出力（キットの JSON と WAV、打点の MIDI）をプラグインが読んで鳴らせれば、M1 の形が早く見える。C++／ONNX への移植はその後。
3. **採譜の改善は並行して、E-GMD の全データと区分 B で。** Phase 0 の持ち越し 1。GPU の学習は夜に回す。

## 2. 最初の 2 週間

| 週 | 作業 | 出口 |
|---|---|---|
| 1 | **区分 B の評価用ステムを作る**（`analysis/eval_midi/` の 7 曲を DAW の VST で書き出し → SpectraLayers で分離。`docs/phase0/評価用ステム一覧.md` の手順）。正解 MIDI 付きの実ステムが初めて揃う | `run_eval.py` で実ステムの本当の M0-1 |
| 1 | **パート分けの自前化の試作（NMFD）**。採譜（CRNN v5）の打点をひな形の初期値にして、ドラムステムをキック／スネア／ハイハット／シンバルに分ける。SpectraLayers のパート別ステムを正解の代わりにして、パートごとの SDR と「パート別の切り出し → 再現」の距離・聞き比べで比べる | NMFD で足りるか、学習モデル（StemGMD）が要るかの判断材料 |
| 1〜2 | **採譜 v6**: E-GMD 全 36,000 本（`--max-tracks 0`）で学習。ゴーストノート（velocity 40 未満）を別の目標にする実験。公開モデル（ADTOF、madmom。評価にだけ使う）との比較 | E-GMD test と区分 B での M0-1 |
| 2 | **JUCE 側: `KitModel` と `SampleVoice`**。`kit.json`（`extract.py` の形式: 種類 → 代表音の WAV、特徴、音量）を読み、層・ラウンドロビン・チョーク・打ごとの音量合わせで鳴らす。Phase 0 の空のプラグインを土台に、Python が作ったキットを MIDI で鳴らす | 「Python で解析 → JUCE で鳴る」が手で通る |
| 2 | **ONNX Runtime をプラグインに入れる試作**。裏のスレッドで `crnn_egmd_v5.onnx` を動かし、Python の推定と一致することを確かめる（対数メルの計算を C++ に移す。`features.py` と同じ設定） | C++ の推定が Python と一致（最大差の数字） |
| 2 | **M1 の受け入れ試験と回帰テストを決める**。区分 A・B の 17 曲で、解析の時間・採譜の F・再現の距離を毎回測る | `run_eval.py` を CI か夜間の定期実行に |

- 2 週間で足りなければ、JUCE 側（4・5 行目）を 3 週目に回す。パート分けと区分 B を先にする（製品の経路の判断が先）。

## 3. Phase 1 全体の段階（目安）

| 段階 | 内容 | 判定 |
|---|---|---|
| 1 | 製品の経路を Python で通す（採譜 → パート分け → 切り出し → キット → 再現）。区分 A・B で測る | SpectraLayers 無しで M0-2 相当（半数以上で「同じキット」）に届くか |
| 2 | 解析の C++／ONNX への移植（対数メル、CRNN の推論、NMFD、切り出し、代表音の選択）。裏のスレッド、進み具合の表示、途中で止められる | 3 分の曲を 1 分以内で解析 |
| 3 | エンジン（`SampleVoice`、チョーク、パートごとの EQ・コンプ、バス、個別出力）と `KitModel` の保存 | pluginval、主要 DAW で動く |
| 4 | UI の最小版（① 解析 ② キット の 2 画面、A/B ボタン、採譜の修正、MIDI の書き出し） | M1: ステムを落として 1 分以内にキットが鳴り、MIDI で DAW に渡せる |

## 4. Phase 0 から持ち越した課題（`docs/phase0/M0判定.md` の順）

1. 採譜の小さい打（ハイハット 0.68、スネア 0.87。E-GMD 全データ、ゴーストノートの別扱い、公開モデルとの比較、区分 B での実測、検証と test の差の原因）。
2. パート分けの自前化（最重要。NMFD か StemGMD の学習モデル）。
3. 打点で説明できない音（タンバリン、残響）の扱い。「その他のパーカッション」か「残差の層」。
4. エフェクトの当てはめの乾いた音の基準（内蔵ライブラリ、モーダル音）とチェーンの範囲（コンプ・歪み・ゲート）。
5. 代表音の選び方の天井（特徴の設計か、聞こえ方に沿った距離の指標）。
