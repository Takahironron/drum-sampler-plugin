## 3. 読み取り

1. **再現は通ったが、採譜はまだ弱い。** 再現が「同じ」に聞こえるのは、直した NMFD が、取りこぼした打の音も近いパートに入れて鳴らし直すから。打点そのもの（MIDI にして DAW に渡すもの）は別の話で、v5 は実ステムで次が弱い。
   - **シンバルをほとんど検出しない**（合計 40。疑似正解 2217）。ハイハットとシンバルを合わせた「金物」でも、a03 51 対 286、a07 98 対 681、a08 16 対 441。金物の音は、スネアやハイハットの代表音に混ざって鳴っている。
   - スネア: a02 は 23 対 148（F 0.246）。ただし a02 のスネアの疑似正解は 148 のうち 86 が −20〜−30 dB の小さい打で、漏れを数えている恐れがある（表の「疑似正解の打の大きさ」: sn24/38/86）。
   - タムを多く出す曲がある（a01 101、a03 126）。SpectraLayers にタムのパートが無いので、合っているかは分からない。
2. **疑似正解の限界。** ハイハットとシンバルの振り分けは、SpectraLayers と v5 で違うことがある（a10: SpectraLayers はシンバル 195・ハイハット 86、v5 はハイハット 148・シンバル 0）。小さい打（−20〜−30 dB）が多いパートは漏れの恐れ。**本当の正解（区分 B）が要る。**
3. a02 の帯域の差は中低域が +4〜5 dB（自己再現 +5.1、方式 C +4.0）。パートの和は元と同じなので、打の区間の境目の扱い（前の打の余韻が鳴っている途中で次の区間が始まる）で余分な音が出ている疑い。聞いて問題になっていないので、原因の確認は後に回す。

## 4. 判定と次の手

**Phase 1 段階 1（製品の経路を Python で通す。SpectraLayers 無しで半数以上が「同じキット」）は合格。** 10 曲とも「同じキット」。条件として残るもの:

- **v5 は製品に入れられない。** 学習の増強（にじみ）に CD 曲のステムを混ぜている（`--bleed-dir data\stems`）。製品用は、にじみも権利の明確な音にして学習し直す（v6）。
- 採譜の取りこぼし（金物、スネア）。再現には効いていないが、MIDI と、キットのパートの割り当て（シンバルの音がシンバルのパートに入る）に効く。

次は段階 2（解析を C++／ONNX に移す）に向けて、**Python の解析を 1 コマンドの参照実装にまとめ**（ステム → キットと MIDI）、**プラグインが MIDI で鳴らした音**を物差しにする。聞き比べてきた `rerender_parts.wav` は、打ごとに特徴の近い代表音を選ぶ Python の描画で、プラグインが MIDI だけで鳴らす音とは選び方が違う。
