## 2. 原因: 打点の合わせ直しが、キックの約 1 割をずらしていた

StemGMD の 12 曲（本当のパート別録音がある）で、キックだけを鳴らした音と、本当のキックの録音との距離を測る。音の選び方（音量だけ = MIDI ／ 特徴 = 方式 C）と、置く位置（MIDI の時刻 ／ 相互相関で合わせ直す = 方式 C）を別々に替える。キットは方式 C と同じ（特徴の k-means の代表 24 音）、1 曲 40 秒、正解の打点。

| 打点の合わせ直し | 音量で選ぶ・MIDI の位置（= MIDI だけ） | 音量で選ぶ・位置を合わせる | 特徴で選ぶ・MIDI の位置 | 特徴で選ぶ・位置を合わせる（= 方式 C） | 自己再現 | 位置が 5 ms 以上ずれる打 |
|---|---|---|---|---|---|---|
| なし（正解の時刻のまま） | 0.415 | 0.368 | 0.405 | 0.351 | 0.224 | 0.5% |
| 旧（1 打ごとに立ち上がりを探す） | **0.494** | 0.373 | 0.460 | **0.351** | 0.229 | **12.0%** |
| **新（種類ごとのひな形に合わせる。3 節）** | **0.372** | 0.357 | 0.346 | 0.334 | 0.222 | 0.8% |

- **旧い合わせ直しでは、MIDI だけ 0.494、方式 C 0.351。** 区分 A の a07 と同じ向きの差がクラウドで出た。差 0.14 のうち、位置を合わせるだけで 0.12 縮む（0.494 → 0.373）。選び方を替えても 0.03 しか縮まない（0.494 → 0.460）。**原因は選び方ではなく位置。**
- 旧い合わせ直しは、正解の時刻をそのまま使う（0.415）より悪い。合わせ直しが、もともと正しい時刻を壊していた。
- 旧い方法は、打ごとに「その後 3 ms の大きさ ÷ その前 6 ms の大きさ」が最大の位置を探す。前の音の余韻や、分離の窓による前ぶれ（プリエコー）、低い音の包絡の波打ちがあると、数 ms〜十数 ms 離れた位置を取る。小さいキック（強さ 40 未満）では 18% が 5 ms 以上ずれた。
- 位置がずれた打は 2 通りに効く。(1) その打の時刻に置いた音の頭が、元の打とずれる。(2) その打から切り出した音は、頭から立ち上がりまでの長さが他と違うので、キットに入ると、使われるたびに位置がずれる。
- 方式 C は、選んだ音を打ごとに元の音と相互相関で合わせて置く（MIDI に無い情報）。だから段階 1 の聞き比べ（方式 C）では分からず、MIDI だけの音を聞いて初めて出た。
- 取りこぼしと時刻の揺れを入れた打点（採譜モデルの打点に似せたもの）でも同じ: 旧 0.763（方式 C 0.629）→ 新 0.711（0.628）。こちらは選び方の差（0.08）が残る。

- **ハイハットの差（0.19〜0.31）も位置ではなく選び方**（位置を合わせても 1.805 → 1.793）。音量だけでは、開閉などの音色の違いを選べない。奏法を別のノートにする（Phase 2 の「細かい分類」）まで残る。
- 新しい合わせ直しの後は、どの種類も「MIDI の位置」と「位置を合わせる」の差が 0.02 以内。**MIDI だけと方式 C の間に残る差は、音の選び方の分だけになった。**

## 3. 直したこと

### 3.1 打点の合わせ直し（`extract.refine_onsets`）

種類ごとに「立ち上がりの形のひな形」を作り、各打をひな形との相互相関が最大になる位置へ動かす。

- 比べるのは、立ち上がりの強さ（1 ms の二乗平均の包絡が、2 ms 前より増えた分。0.25 ms 刻み）。ひな形は、各打の前 30 ms〜後 20 ms をその中の最大で割り、打をまたいで中央値を取ったもの。
- 動かす幅は、元の時刻から ±20 ms と、隣の同じ種類の打との間隔の 0.45 倍の小さい方まで。比べる区間も、隣の同じ種類の打の手前までに限る（装飾音や連打で、隣の打の立ち上がりに引かれない）。
- ひな形を作り直しながら 3 回繰り返す。最後に、包絡のひな形の立ち上がり（谷から山までの 10% の高さを上向きに超える位置）を打点にする。
- 同じ種類の打は、立ち上がりの同じ位置に時刻がそろう。切り出した音の頭から立ち上がりまでの長さもそろうので、どの音をどの打の時刻に置いても位置が合う。
- 打が 4 つ未満の種類は旧い方法のまま。端の打、音の無い打、隣が近すぎる打は動かさない。

正解の時刻との差のばらつき（種類ごとの一定のずれを引いた後）が 5 ms を超える打の割合。旧 → 新。打を全部まとめた数（1 曲 40 秒。キック 520〜790 打、スネア 480〜780 打、ハイハット 1190〜1750 打）:

| | StemGMD 正解の打点 | StemGMD 取りこぼしあり | E-GMD 正解の打点 | E-GMD 取りこぼしあり |
|---|---|---|---|---|
| キック | 11.2% → **0.8%** | 9.1% → **1.3%** | 4.3% → **1.0%** | 4.5% → **1.2%** |
| スネア | 7.3% → 2.4% | 3.8% → 2.0% | 8.8% → 8.3% | 5.2% → 6.2% |
| ハイハット | 9.1% → 5.2% | 10.6% → 8.0% | 14.7% → 8.3% | 16.2% → 9.8% |

- 「取りこぼしあり」の打点は、合わせ直す前は 33〜39% が 5 ms を超える（採譜の時刻は約 10 ms 刻み）。
- キックはどの強さでも 1% 前後になった（StemGMD、強さ 40 未満: 18.2% → 1.1%）。
- **スネアの小さい打（強さ 40 未満）は直っていない**: StemGMD 14.8% → 5.3%、E-GMD 27.3% → 28.1%（取りこぼしありでは 30% → 38%。40 打なので差は 3 打）。隣の打が 60 ms 以内にある打も悪い（スネア 5〜32%、ハイハット 21〜52%）。
- ずれが残る打は、ひな形との相関が低い打に集まる。相関が 0.9 以上の打（キックの 85〜94%、スネアの 52〜82%、ハイハットの 53〜65%）は、ずれるのが 1.4% 以下（キックとスネアは 0.2% 以下）。0.6 未満の打は 2〜7 割がずれる。相関は `refine_onsets(..., stats=…)` で取れる（計画書の「信頼度表示」の材料）。
- 打点の位置（正解の時刻との一定の差）は、キックが 0.6〜0.9 ms 後ろ、スネアが ±0.5 ms、ハイハットが 1.3〜3.0 ms 手前（分離の窓による前ぶれが先に上がる）。種類の中では一定なので、音の位置は変わらない。

### 3.2 MIDI 用のキット（`extract.build_kit_by_level`。製品のキット）

種類ごとに、音量の順に 24 個の区分（同じ数ずつ）に分け、各区分から「普通の音」を 1 つずつ選ぶ。普通の音 = 音色（減衰・明るさ・帯域のエネルギー）がその区分の中央に最も近く、余韻の途中で切れていない音（終わりの大きさがピークより 35 dB 以上小さい）。分離の確からしさの低い打からは取らない（これまでと同じ）。

MIDI では音量だけで音を選ぶ。これまでのキット（特徴の k-means の代表）は音色のばらつきを覆うように選ぶので、他の音が混ざった打や余韻の切れた打も代表になり、音量の近い普通の打に当たっていた。

| 特徴の k-means の代表（これまで） | 1.041 | 1.537 | 0.917 | 1.178 |

- 下がり幅は 0.02〜0.08。効くのはハイハット（本当のハイハットとの距離 1.840 → 1.747）とスネア（取りこぼしあり 0.866 → 0.822）。キックは変わらない（0.371 → 0.375）。
- 方式 C の距離（`rerender_parts.wav`）は、これまでどおり k-means の代表で測る（過去の記録と比べられるように）。
- **副作用: 超高域（10 kHz 以上）が少し下がる。** StemGMD（1 曲 60 秒、正解の打点）で、「MIDI だけ − 元」の超高域は、k-means のキットが −0.3 dB、このキットが −1.2 dB（余韻の優先を外しても −1.0 dB）。ハイハットだけを鳴らしてそのパートと比べると、k-means のキットは超高域 +0.4 dB（低域は +7.4 dB。他の太鼓の漏れを含む音が代表に入っている）、このキットは −1.3 dB（低域 +5.5 dB）。各音量帯の「普通の音」を選ぶと、開いたハイハットなどの明るい・長い打の分のエネルギーが出ない。E-GMD では差が小さい（高・超高とも −0.6 → −0.8 dB）。
- 区分の中心を「エネルギーの平均」にしても戻らない（5 節）。音量だけで音を選ぶ限り残り、奏法の分類（Phase 2）で扱う。**耳で「こもる」と感じるかは、Takahiro の聞き比べで確かめる**（`rerender_midi_km.wav` が、同じ打点を k-means のキットで鳴らした音。7 節）。

### 3.3 その他

- **MIDI の時刻の刻み**: `hits.mid`／`hits_model.mid` を 1 拍の 480 分の 1（120 BPM で約 1 ms）から 960 分の 1（約 0.5 ms）にした。打点が 1 ms 以内でそろうようになったので、書き出しの丸めを小さくする。
- **自己再現の切り方**: 各打の区間を、キットの音と同じく打点の 2 ms 前から取る。キックの打点は立ち上がりの頭より少し後ろなので、打点ちょうどで切ると前の区間のフェードが立ち上がりの頭に掛かっていた。
- **`run_eval.py` の表に足した列**（区分 A で原因を見分けるため）:
  - 「種類ごとの距離」: その種類だけを鳴らした音と、そのパートの音（キットを切り出した元）との距離。MIDI だけ／方式 C／自己再現。混ざった音の距離では、キックやスネアの違いはハイハットやシンバルの差に埋もれる。2 節の表と同じ見方を、本当のパート別録音が無い曲でもできる。
  - 「MIDI だけの損失の内訳」: その種類だけ自己再現に置き換えたときの、混ざった音の距離の下がり幅。
  - 「STFT（MIDI だけ、k-means のキット）」と `rerender_midi_km.wav`: 同じ打点を、これまでのキット（特徴の k-means の代表）で鳴らしたもの。キットの選び方だけを聞き比べられる。
  - 「位置が 5 ms 以上ずれる打の割合」: MIDI の時刻に置いた代表音を、その打の元の音に相互相関で合わせ直したときに 5 ms より大きく動く打の割合。**目安**: 正解の時刻で確かめると、本当に 5 ms 以上ずれた打の 4〜8 割を拾い、ずれていない打も 0.2〜1.5%（ハイハットは 1〜7%）数える。低い音のキックは周期ぶん滑った位置でも相関が高いので（E-GMD の 1 曲で、打点は全部 2 ms 以内なのに 34% と出た）、MIDI の位置より 1.25 倍以上良い位置だけを数えるようにした。
- **見つけて直した不具合**:
  - 「方式 C の損失の内訳」は、残りの種類を位置合わせなしで鳴らして比べていた（方式 C に位置合わせを入れたときから）。全体に低く出て、全部の種類が負になる曲があった。同じ鳴らし方で比べるように直した。これより前の表のこの列とは比べられない。
  - 曲の頭ちょうど（0.000 秒）に打がある曲で、`label_offset.txt` が −0.1 ms だと、その打が正解から落ちていた（StemGMD の s07 と s08。自己再現が 0.05 → 0.26 に見えた）。区間の頭の 5 ms 手前までの打は、頭の打として残す（`stems.truth_hits_in_window`）。StemGMD の標本には `label_offset.txt` は要らないので、クラウドのものは消した（測っても 0.1〜1.2 ms）。
