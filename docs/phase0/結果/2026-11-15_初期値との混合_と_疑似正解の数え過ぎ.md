## 2. 疑似正解はキックを約 3 倍に数え過ぎていた

### 気づいたきっかけ

疑似正解のキックの数が、曲のテンポから考えて多すぎる。

- a07（トランス）: 4 つ打ちなら 1 分に 130〜140 回前後のはず（テンポは未確認）だが、疑似正解は 255。v5 の検出は 137。
- a06（電子系）: 疑似正解 128、v5 の検出 144。4 つ打ちとして妥当な数なのはこの曲だけで、v5 の F も 0.905 と高い。
- ロックの a01〜a04 は 1 分に 360〜421（1 秒に 6〜7 回）。v5 の検出は 112〜151。

### 確かめた（StemGMD の本当の単独録音 12 曲）

疑似正解を作る `onsets_from_part` を、漏れの無い本当のパート別の録音に掛けて、正解の MIDI と比べた。

| | キック | スネア | ハイハット |
|---|---|---|---|
| 作り直す前、漏れなし: 検出／正解（適合率、再現率、F） | 2226／742（0.40、0.98、**0.52**） | 883／781（0.80、0.88、0.80） | 1635／1751（1.00、0.93、0.96） |
| 作り直す前、他のパートが −30 dB で漏れる | 2247（0.38、0.98、0.51） | 1462（0.44、0.88、0.55） | 1931（0.83、0.92、0.87） |
| **作り直した後**、漏れなし | 727（0.99、0.97、**0.98**） | 561（1.00、0.81、0.88） | 1613（1.00、0.92、0.96） |
| 作り直した後、−30 dB で漏れる | 744（0.97、0.97、0.97） | 573（0.99、0.81、0.88） | 1651（0.97、0.92、0.94） |
| 作り直した後、−20 dB で漏れる | 952（0.74、0.97、0.83） | 842（0.70、0.82、0.70） | 1656（0.95、0.91、0.92） |

- 作り直す前は「約 12 ms 前より 6 dB 大きく、無音に近くない」だけで拾っていた。検出 2,226 個の内訳は、キックと同時 727、**他の太鼓の打と同時 443（大きさの中央値 −32 dB）、どの打とも合わない 1,056（−35 dB。キックの余韻の途中）**。余分な約 1,500 個は、大きいキックより 30 dB 以上小さいものが大半。
- スネアは漏れがあると数え過ぎる（適合率 0.44）。ハイハットは元からほぼ正確。
- **作り直した検出**（`drumeval/baseline.py`）: その種類の帯域（キック 25〜180 Hz、スネア 150 Hz 以上、ハイハット 3 kHz 以上、タム 50〜600 Hz、シンバル 2 kHz 以上）の包絡（直前 20 ms の二乗平均）が、**その前 60 ms の平均**を 6 dB 以上超えた瞬間を打点にする。大きい打（上位 5%）より 30 dB 以上小さいものは捨てる。余韻の揺れは平均を大きくは超えないので、数え過ぎない。
- 限界: ごく弱いゴーストノート（強さ 20 未満）は落ちる（スネアの再現率 0.81。ファンクの 1 曲で疑似正解 64 対 本当 124）。漏れが −20 dB と大きいステムでは、まだ数え過ぎる（適合率 0.70〜0.74）。表の「疑似正解の打の大きさ」の列で、小さい打（−20〜−30 dB）が多い種類は漏れを疑う。
- 途中で試して捨てたもの: ヒルベルト変換の包絡（打点の前に裾を引き、無音の後の打を 80 ms 早く拾う）、直前の最小との比較（揺れに弱い）。

## 3. これまでの数字への影響

| これまでの記録 | 影響 |
|---|---|
| 区分 A の「疑似正解に対する F 値」（2026-10-31〜11-13 の各表） | **キックは低く出ていた**（正解の側が 3 倍）。スネアも漏れのぶん低い。ハイハットはほぼそのまま。v5 のキックの本当の精度は、表の 0.34〜0.94 より高い見込み |
| v5 のハイハットとシンバルの取りこぼし | **本物**。ハイハットの疑似正解は正確で、v5 の検出は 1617 対 2975。シンバルは 39 対 1929 でほぼ検出しない |
| 微調整の効果（2026-11-13「採譜 0.555 → 0.727」） | キックの分は、**数え過ぎたラベルを学んだ分を含む**。微調整したモデルはキックを v5 の 2.5 倍検出する（2875 対 1169）。a06 は 476（本当は約 128）。**MIDI には余分なキックが出る。** ハイハットとシンバルの改善は本物の見込み |
| 段階 1 の聞き比べ（9／10 が「同じ」、2026-11-15） | 聞いて「同じ」は有効。ただし、数え過ぎた打点は聞き比べでは分かりにくい（下の表）。a06 を「疑似正解の側が取りこぼしている可能性」と書いたのは誤りで、数え過ぎていたのはモデルの側 |
| M0-2（SpectraLayers の経路、2026-11-10） | 聞いて「同じ」は有効。切り出しに使った打点が数え過ぎだったので、キックの代表音は断片だった見込み |
| M0-1（E-GMD test 0.773）と M0 判定 | 影響なし（正解は MIDI） |

数え過ぎた打点が再現とキットに与える影響（StemGMD、直した NMFD）:

| 打点 | 1 曲の打 | 自己再現 | 方式 C | キックの代表音の長さ（中央値） | 代表音の純度 キック／スネア |
|---|---|---|---|---|---|
| 正解（MIDI） | 284 | 0.082 | 0.878 | 0.75 秒 | +29.6／+17.7 dB |
| 数え過ぎた打点（作り直す前の疑似正解） | 397 | 0.127 | 0.893 | **0.30 秒** | **+15.1／+13.4 dB** |
| 作り直した疑似正解 | 245 | 0.139 | 0.849 | 0.74 秒 | +30.0／+19.6 dB |

- **再現の距離はほとんど変わらないが、代表音が断片になり、純度が落ちる。** 同じパターンを鳴らし直す聞き比べでは分かりにくく、キットを別のパターンで鳴らすとき（仕様 4）と、MIDI を DAW に渡すとき（M1）に効いてくる誤り。
- 直す前の NMFD は、打点が多いほど有利だった（窓が増えて、消える音が減る）。直す前の NMFD に作り直した疑似正解を与えると自己再現 3.20（正解の打点で 2.76）。微調整で製品の経路の距離が大きく下がった（3.72 → 2.22）一因はこれ。
