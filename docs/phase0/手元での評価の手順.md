# 手元（Windows）で評価を走らせる手順

分離したステムを PC から出さずに、3 指標の表を作るまでの手順。所要は初回 20〜30 分（Python の導入込み）。

## 1. 道具を入れる（初回だけ）

1. **Git for Windows**: https://git-scm.com/download/win から入れる（既に入っていれば不要。PowerShell で `git --version` が出れば入っている）。
2. **Python 3.10 以上**: https://www.python.org/downloads/windows/ から入れる。インストーラーの最初の画面で **「Add python.exe to PATH」にチェック**を入れる。PowerShell で `python --version` が出れば入っている。

## 2. リポジトリを取る（初回だけ）

PowerShell を開き、置きたい場所（例: `D:\Music`）で次を実行する。

```
cd D:\Music
git clone https://github.com/Takahironron/drum-sampler-plugin.git
cd drum-sampler-plugin
git checkout claude/funny-pascal-pmmnoh
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r analysis\requirements.txt
```

- `Activate.ps1` が「スクリプトの実行が無効」で止まったら、`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を一度実行してからやり直す。
- 2 回目以降は `cd D:\Music\drum-sampler-plugin` → `.\.venv\Scripts\Activate.ps1` だけでよい。
- 最新を取り込むときは `git pull`。

## 3. ステムを置く

分離したドラムのステム（WAV）を次の形に置く。`data\` はコミットされない（`.gitignore` 済み）。

```
data\stems\a01\drums.wav
data\stems\a02\drums.wav
...
data\stems\a10\drums.wav
```

- 曲 ID と曲の対応は `docs\phase0\評価用ステム一覧.md` の区分 A の表。
- SpectraLayers の書き出し（`drum.wav` と他の楽器の WAV、キック.wav などのパート別ステム）をフォルダごと置いてもよい。`drum.wav` を自動で選び、パート別ステムがあれば疑似的な正解として使う。
- 長さはそのままでよい（評価は既定で先頭 60 秒を使う。前奏が長い曲は `--max-seconds 0` で全部使うか、先に DAW で切る）。
- 分離した WAV がまとめて 1 つのフォルダにあるなら、次で自動的に上の形にできる（モノラル FLAC、先頭 90 秒。ファイル名を `a01_...` で始め、開始秒を `@45` のように付けられる）。

```
python analysis\pack_stems.py <分離したWAVのフォルダ> data\stems --seconds 90
```

## 4. 評価を走らせる

```
pip install onnxruntime
python analysis\run_eval.py data\stems --model analysis\models\crnn_synth_v0.onnx --threshold 0.3 --render --out data\results\YYYY-MM-DD.md
```

- `--model` は合成データで学習した小さな採譜モデル（ONNX）。付けなければ学習なしの基準値で推定する。`--threshold` は打点のしきい値（既定 0.5。実ステムでは 0.3 の方が取りこぼしが減る見込み）。
- パート別ステムがある曲では、疑似正解を `hits_pseudo.csv` と `hits_pseudo.mid` に書く。MIDI を DAW に読み込み（120 BPM、1 小節目の頭 = 0 秒）、`original_cut.wav` と並べると、疑似正解の誤りを目と耳で確かめられる。
- `--render` を付けると、各曲のフォルダに聞き比べ用の WAV ができる: `original_cut.wav`（元、同じ長さ）、`rerender_mix.wav`（混ざったドラムから切り出したキットで鳴らし直し）、`rerender_parts.wav`（パート別ステムから切り出したキットで鳴らし直し。パート別ステムがある曲だけ）。
- 1 曲 30〜60 秒ほどで、`--out` の Markdown に表ができる。このファイルをチャットに添付するか、中身を貼る。**出力先は `data\results\` にする**（`docs\phase0\` に出すと、こちらがコミットする記録と名前がぶつかって `git pull` が止まる）。
- `--render` で各曲のフォルダにできる WAV: `original_cut.wav`（元）、`rerender_self.wav`（各打をその打自身の区間で鳴らし直し。打点と区間の切り方だけの損失）、`rerender_parts.wav`（パート別に切り出した 3 層 × 3 音のキットで鳴らし直し）、`rerender_mix.wav`（混ざったドラムから切り出したキット）、`kit_parts_audition.wav`（切り出した音を 種類 → 層（弱→強）→ ラウンドロビン の順に並べたもの。切り出しそのものの質を聞く）。

## 5. 聞き比べ用の WAV を作る（M0-2）

曲ごとに、切り出したキットで鳴らし直した WAV を作る。

```
python analysis\baseline_transcribe.py data\stems\a01\drums.wav data\stems\a01\est.csv
python analysis\extract_kit.py data\stems\a01\drums.wav data\stems\a01\est.csv data\stems\a01\kit --render data\stems\a01\rerender.wav
```

`drums.wav`（元）と `rerender.wav`（再現）を交互に聞いて、「同じキットに聞こえる／違う」を `docs\phase0\M0判定.md` の表に書く。切り出した音は `kit\` に層ごとの WAV で入る。

## 6. Remote Control で頼む場合（任意）

リポジトリのフォルダで `claude remote-control` を起動すると、アプリにそのセッションが出る。そこに次のように頼めば、上の 4 と 5 を代わりに実行して結果を見せてくれる。

```
.venv を有効にして python analysis\run_eval.py data\stems --out docs\phase0\結果_2026-10-26.md を実行し、できた表を見せて。
```

結果の表はクラウド側のセッション（この手順書を書いた側）に貼れば、読み取りと次の手をそちらで進められる。

## 困ったとき

- `git pull` が「untracked working tree files would be overwritten」で止まる → 手元で作ったファイルがこちらのコミットと同名。そのファイルを `data\` に移してから `git pull`。

- `python` が見つからない → Python のインストーラーで PATH のチェックを忘れている。再インストールするか、`py -3` を `python` の代わりに使う。
- `pip install` で `mir_eval` や `soundfile` が失敗する → `python -m pip install --upgrade pip` の後にやり直す。
- `run_eval.py` が「drums.wav のあるフォルダが見つからない」と言う → フォルダ名とファイル名（`drums.wav` か `drums.flac`）を確かめる。
